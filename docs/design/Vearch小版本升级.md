# 自研版本管理

自研版本管理页面显示了vearch各个发布版本对应的oss地址等信息，目前只包含几个常用的发布版本。

![](./assets/Vearch小版本升级.assets/mqygZfPPS0XsJkdeUd8c.png)
**新建**：可以新增版本信息，版本号不能重复

**修改**：更新版本信息，更改Vearch或gamma地址等

**新增版本关系**：新增版本升级关系，目标版本表示升级的最终版本，原版本表示支持升级到目标版本的最低要求版本号。如果指定了自动升级版本就升级到指定版本。

![](./assets/Vearch小版本升级.assets/nrv5xeOK1ZSNxA5y3h2k.png)
版本关系页面如下，这里也可以新增版本关系或更新：

![](./assets/Vearch小版本升级.assets/NjksGw1AlS9pbj4KTpXF.png)
例如：v3.5.6.1-v3.5.9表示3.5.6.1,3.5.7,3.5.8都可以升级到3.5.9版本，但3.5.6不行。

 


**删除**：删除版本信息

# 自动升级管理

## 集群列表

![](./assets/Vearch小版本升级.assets/IWkcBvQtitYCXJEQmtxI.png)
显示当前vearch创建的多有集群列表信息，可以批量加入白名单列表中，并支持根据集群级别和集群名称过滤集群信息。

 


## 白名单列表

![](./assets/Vearch小版本升级.assets/P1A6avI8Wk5fGAmWIXmZ.png)
**加入升级列表**：支持批量加入和指定集群加入。加入到升级列表中的集群会在升级列表中显示，并默认设置升级时间为次日凌晨进行自动升级。

**设置自动升级时间**：支持批量设置和指定集群设置，设置集群的自动升级时间。对于未设置自动升级时间的集群，**集群升级检测定时任务**扫描到之后会将集群的自动升级时间设置为半年以后

**延期**：目前延期时间支持一周，一个月，一年。

**移除白名单**：将集群从白名单列表中移除。

 


**集群升级检测定时任务（每天十点）**：

1.对白名单列表中未设置升级日期的集群，设置自动升级日期为半年后。

2.对于“自动升级日期”小于“发送邮件最晚截止日期”（目前设置发送邮件为提前一周发送，ducc配置）内的集群，首先根据集群的当前版本号和升级版本关系，确定集群升级的目标版本号，不能确定目标版本号则直接跳过。然后根据upgrade_limit（每日集群升级个数的最大限制，当前值为3，ducc可配置）和自动升级日期重新设置集群的自动升级日期（例如两日后设置自动升级的集群个数超过upgrade_limit限制后，超过限制的集群会自动延期）

3.对于调整后的集群，如果新的自动升级时间仍然满足小于“发送邮件最晚截止日期”，向集群负责人发送升级邮件通知，集群负责人可根据实际情况判断是否延期。

4.对于调整后的集群，若新的自动升级日期为次日，则将集群加入到升级列表中。

 


## 升级列表

![](./assets/Vearch小版本升级.assets/3pc79IZQS6t0Q5yhpCKH.png)
升级列表维护了所有待升级，升级进行中，升级失败，已升级的升级集群列表信息。升级状态表示升级任务的执行状态。

批量操作：

**1.批量删除**：批量删除升级列表中的集群信息。

**2.批量设置自动升级时间**：对于升级列表中的集群，批量设置新的升级时间，一般用于操作待执行的集群。

**3.手动执行版本升级任务**：对于选中的集群，执行批量手动升级任务，手动升级会立刻开始执行升级操作。

单集群操作：

**1.更新升级目标版本**：更新目标升级版本，更新时只检查了更新版本是否存在自研版本信息列表中，是否可执行升级操作需要业务研发判断。例如目前支持v3.5.6.1-v3.5.9的升级，但对于特殊需求需要升级到v3.5.8版本的用户，需要手动更新升级目标版本号。

**2.升级**：对当前集群手动执行升级操作，升级操作会立即升级。

**3.暂停**：暂定升级任务，只能对进行中或升级失败的集群执行暂停操作。自动升级任务执行是串行操作，暂停升级进行中的集群或者集群失败之后后续的集群升级操作都不会执行。

**4.继续**：继续执行自动升级任务。暂停或者回滚完成的任务才能执行继续操作，回滚任务继续执行表示继续执行升级操作。点击继续后会重新立即执行所有待自动升级的任务。注意该操作的执行时间，是否会对业务产生影响。

**5.回滚**：回滚集群节点到原版本。对于待执行和正在进行中的集群不能执行回滚操作。集群在升级节点列表中还存在状态为“自动升级中”的节点时，也不允许进行回滚。

**6.删除**：删除升级任务。对于升级成功的任务记录，若集群还未下线，不允许删除该记录，便于后续统计分析升级情况或升级历史。

**7.设置自动升级时间**：修改集群的自动升级时间。一般不需要在这里操作。假设2026-03-25修改了集群的自动升级时间为2026-03-31，对于待执行的集群，凌晨的自动升级任务判断当前集群的升级日期晚于当前日期，会将该任务从升级列表中移除，后续通过**集群升级检测定时任务**再重新加入到升级列表中。当前未对修改已升级成功的升级任务的自动升级时间做限制，一般不应该这样操作。

 


**自动升级任务（每天零点）**

1.自动升级任务每天凌晨两点执行，首先获取升级列表中所有待执行的升级任务，若自动升级时间已延迟，则将任务从升级列表中移除，目标升级版本信息不存在时忽略该升级任务。

2.自动升级任务串行执行，当某个升级任务暂停或者升级失败时跳过后续所有的升级任务。

 


## 升级节点列表

![](./assets/Vearch小版本升级.assets/PFCaw4zOmbA52mMwnMoZ.png)
 


手动执行升级任务或者自动升级任务执行时会将集群对应的所有升级节点加入到升级节点列表中，研发或运维人员可以通过升级节点列表获取节点的升级执行进度和状态。

节点升级也是串行执行的，当某个节点升级失败时，会中断后续所有节点的升级，并修改集群对应的升级任务的状态为“升级失败”。

若节点实际已升级成功，但当前实现逻辑的问题误判节点升级失败时，这种情况并不实际影响集群的升级操作，但需要研发或运维介入，将误判为升级失败的节点从节点升级列表中移除，再通过执行**“升级列表”**页面的**“暂停”**和**“继续”**操作，恢复自动升级任务的执行。
